# MC 自动翻译工具 - 上下文维护

> 最后更新：2026-08-13（Windows / PowerShell 环境）
> 用途：记录项目结构、构建环境、近期改动与已知坑，便于后续接手。

## 1. 项目定位
- 名称：MC 自动翻译工具 / MC Auto Translation Tool
- Minecraft Java 版公益开源纯客户端全界面翻译模组。
- 默认本机离线模型（仅 127.0.0.1）；可选 LibreTranslate / 腾讯混元 / OpenAI 兼容 LLM。
- 快捷键：`U` 打开设置，`F8` 一键开关翻译（可在按键绑定改键）。

## 2. 模块结构（根 settings.gradle）
- translator-core：共享核心逻辑（40 个 java 文件，包 org.universaltranslator.core）
- platform-fabric-1.21.11：Fabric，Java 21，已发布
- platform-fabric-26.1：Fabric，Java 25，开发中（已过构建/Mixin/主菜单检查）
- platform-fabric-26.2：Fabric，Java 25，开发中（已过干净构建/重混淆）
- legacy/forge-1.8.9、legacy/forge-1.12.2：独立 Forge 工程，各自带构建文件，不在根 Gradle 内
- platform-forge-legacy-common：Forge 旧版共享代码

  `set "JAVA_HOME=D:\封装\环境库\jdk25"` 与 `set "PATH=%JAVA_HOME%\bin;%PATH%"`

- 语言文件已含 screen.universal_translator.llm.* 文案（zh_cn / zh_tw / en_us）。

### 5.2 翻译速度优化（重点：标题类一闪而过文本）
- translator-core/TranslationCoordinator.java：
  - 执行队列由 ArrayBlockingQueue 改为 PriorityBlockingQueue。
  - 新增 PrioritizedTranslationTask（按优先级 + 提交序号排序，同级保持 FIFO）。
  - priorityOf(TextKind)：TITLE/SUBTITLE/ACTION_BAR/BOSS_BAR/TOAST = 0（最高）；
    CHAT/SYSTEM_MESSAGE/DISCONNECT_REASON = 10；容器/物品/提示/告示牌/书 = 20；
    记分板/玩家列表 = 40；其余背景 = 80。
  - 在线 worker>1 时新增 dedicated urgent executor（最多 2 个 urgent worker），TITLE/ACTION_BAR/BOSS_BAR/TOAST 不再被普通文本 API 队列堵住。
  - 普通队列 MAX_QUEUED_TRANSLATIONS=128；urgent 队列 MAX_QUEUED_URGENT_TRANSLATIONS=64。
- translator-core/RenderTranslationSession.java：
  - 提交限流分级：urgent 30/s、priority 16/s、background 4/s。
  - TITLE/SUBTITLE/ACTION_BAR/BOSS_BAR/TOAST 走 urgent 窗口；
    聊天/物品/容器/提示等走 priority；世界空间/HUD 噪声走 background。
  - 渲染 lookup 会先同步读取持久/内存缓存：已翻译过的文本首帧直接显示译文，不再等后台回调。
  - urgent 文本首次未命中缓存时不再在渲染线程短等；先立即返回原文，避免标题出现瞬间卡顿，后台完成后写入缓存。
- translator-core/PersistentTranslationCache.java：
  - 缓存 key 使用 SHA-256 哈希，不明文保存原文 key。
  - 译文 value 以本地明文 UTF-8 Properties 保存，进程退出/重新进入存档后仍可加载并首帧命中。
- platform-fabric-{1.21.11,26.1,26.2}/.../FabricTranslationRuntime.java：
  - 在线 API 并发 worker 数由 2 提升到 4；离线模型仍保持 1（避免本地模型抢 CPU）。
- platform-fabric-1.21.11/.../InGameHudContextMixin.java + RenderedTextBridge.java：
  - 在 HUD 接收 TITLE/SUBTITLE/ACTION_BAR 时立即预热翻译，不等到渲染帧才提交。
  - 翻译完成后通过客户端线程回放 HUD 文本，标题/副标题显示 60 ticks，避免一次性标题消失后只能等第二轮。
- 验证：2026-08-12 已运行 `:translator-core:test`，BUILD SUCCESSFUL in 10s；已运行 `:platform-fabric-1.21.11:build --no-daemon --stacktrace`，BUILD SUCCESSFUL in 13s。
- 自检新增：urgent 标题绕过阻塞普通队列、标题 lookup 不阻塞渲染线程、重启后持久缓存首帧命中且不再调用 provider。

## 6. 已知约束
- 离线模型（llama.cpp）单 worker，提速主要靠缓存与优先级，不要盲目加离线并发。
- 腾讯混元 provider 内置 60ms 最小请求间隔（合理限速，未改动）。
- 首次出现且无缓存的标题仍受外部 API 实际响应时间影响；现在不再卡渲染线程，译文返回后会主动回放显示一次，并写入缓存供后续直接命中。
